Methodology & interpretation

Each case decodes its source before mounting, warms up for 30 animation frames, then samples 120 requestAnimationFrame intervals. First-frame time includes renderer creation, shader compilation and scheduling, but excludes media download and decode. CPU submission measures JavaScript and WebGL calls, excluding asynchronous GPU work. Timing precision is browser-limited; tiny differences are not evidence of a speedup.

Frame intervals were similar before and after. These short runs do not measure sustained thermal performance, GPU completion, battery use or every device. Keep the tab visible; a visibility interruption invalidates the run. Reduced motion must be disabled to measure animation.

Sizes use esbuild 0.28.2, minified ESM targeting ES2020, tree shaking and gzip level 9. Decimal kB (1,000 bytes); excludes sample media and playground UI. Reproduce with npm ci && npm run measure:size.

Less work for each frame.

50% less intermediate memory

A two-layer composition now needs one RGBA8 target instead of two. At 960 × 540, that saves 2.07 MB. Three or more layers reuse two targets. This excludes source textures, canvas and driver overhead.

Allocate once. Update in place.

Video textures reuse storage until source dimensions change. Both reference video runs used one source storage allocation. Subsequent uploads update that storage in place.

Simple by design

One active-layer list per draw. No runtime dependencies. Hidden and offscreen canvases stop rendering; the native image or video stays available if WebGL fails.
